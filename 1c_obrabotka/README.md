# Внешняя обработка «Отправка документов в TMS» (вариант A — push из 1С)

Аналог обработки Saby: в 1С через **Дополнительные отчёты и обработки** появляется
команда **«Отправить в TMS»** в формах документов **Расходная накладная (УПД)** и
**Счёт на оплату**. По нажатию обработка формирует **PDF печатной формы** и POST-ит
её в TMS, который прикрепляет файл к нужному заказу.

```
1С (обработка .epf)  ──POST PDF──►  TMS  POST /api/1c/order-document  ──►  AttachedFile заказа
```

Преимущество перед расширением (.cfe, вариант B): `.epf` грузится самим
пользователем через «Доп. обработки» по вебу (как Saby) — доступ к серверу базы
и помощь хостинга не нужны.

---

## Состав

- `ОтправкаВTMS_Модуль.bsl` — код модуля объекта внешней обработки (вся логика).
- Приёмная сторона TMS: `app/routers/api_1c.py` (эндпоинт `POST /api/1c/order-document`).

---

## Шаг 1. Настроить TMS (сервер)

1. Сгенерировать ключ, например:
   ```bash
   python -c "import secrets; print(secrets.token_urlsafe(32))"
   ```
2. Добавить его в `.env` TMS:
   ```
   ONEC_PUSH_KEY=<сгенерированный-ключ>
   ```
3. Перезапустить TMS. Без `ONEC_PUSH_KEY` эндпоинт отвечает `503` (приём выключен).

> Заказы, к которым шлём документы, должны быть **выгружены из TMS в 1С** (у заказа
> заполнен `external_id_1c`) — иначе TMS вернёт `404` «заказ не найден». Это
> происходит штатно при подтверждении заказа (`push_order`).

## Шаг 2. Собрать `.epf` (Конфигуратор, учебная платформа 8.5.1 подойдёт)

1. Конфигуратор → **Файл → Новый → Внешняя обработка**.
2. Имя обработки: `ОтправкаВTMS`.
3. Открыть **Модуль объекта** → вставить весь код из `ОтправкаВTMS_Модуль.bsl`.
4. **Заполнить 4 константы** в начале модуля (область «КонстантыНастройки»):
   - `ХОСТ_TMS` — хост TMS без схемы и пути (напр. `tms.life-it.pro`);
   - `ПОРТ_TMS` — `443` (HTTPS) или ваш порт;
   - `HTTPS_TMS` — `Истина`/`Ложь`;
   - `КЛЮЧ_API` — то же значение, что `ONEC_PUSH_KEY` в `.env` TMS.
5. **Файл → Сохранить как…** → тип **Внешняя обработка (*.epf)** → `ОтправкаВTMS.epf`.

> Обработка собрана на платформе 8.5.1 — загрузится в серверную УНФ 8.5.1 без
> проблем совместимости.

## Шаг 3. Загрузить в УНФ (как Saby)

1. В 1С:Предприятии: **НСИ и администрирование → Печатные формы, отчёты и
   обработки → Дополнительные обработки → Добавить из файла** → выбрать `ОтправкаВTMS.epf`.
2. На предупреждение про небезопасный режим — **согласиться** (обработка ходит в
   интернет, как Saby).
3. Команда «Отправить в TMS» автоматически зарегистрируется для документов
   «Расходная накладная» и «Счёт на оплату».

## Шаг 4. Проверить

1. Открыть проведённую **Расходную накладную** (по заказу, выгруженному в 1С) →
   **Ещё → Отправить в TMS** (или выделить строки в списке → та же команда).
2. Внизу появится сообщение «TMS: отправлено 1, ошибок 0.».
3. В TMS открыть карточку заказа → в блоке документов появится **УПД (PDF)**.
4. Аналогично из **Счёта на оплату** → прикрепится **Счёт (PDF)**.

---

## Как определяется заказ в TMS

Обработка шлёт все доступные GUIDّ, TMS выбирает заказ по приоритету:

| Источник в 1С | Параметр | Поле TMS |
|---|---|---|
| Расходная.Заказ / Счёт.Заказ | `order_ref` | `Order.external_id_1c` |
| Расходная накладная (сам документ) | `shipment_ref` | `Order.shipment_id_1c` |
| Счёт (сам документ / основание расходной) | `invoice_ref` | `Invoice.external_id_1c → order` |

Идемпотентность — по `external_key = "<guid>:<тип>"`: повторная отправка заменяет
прежнюю версию файла, дубль не плодится.

## Что уточнить под вашу редакцию УНФ

- **Имена макетов печати** Счёта/УПД. Обработка перебирает стандартные кандидаты и
  берёт первый сработавший; если ни один не подошёл — в сообщении будет список
  опробованных макетов и менеджер печати, добавьте правильное имя в строку
  `Кандидаты` соответствующего типа в `ОтправитьОдинДокумент`. Где взять точный
  идентификатор макета: Конфигуратор → Документ → Команды/Макеты печати, либо
  модуль менеджера документа (процедура `Печать`/`ДобавитьКомандыПечати`).
- **Печать через БСП**: используется `УправлениеПечатью.СформироватьПечатныеФормы`,
  модуль резолвится в рантайме через `Вычислить("УправлениеПечатью")`. Это нужно
  потому, что обработка **собирается на учебной платформе** (где конфигурации УНФ и
  её модулей нет → синтакс-контроль ругается «Переменная не определена»), а
  **работает на боевой УНФ**, где модуль есть. Если в вашей УНФ модуль печати назван
  иначе — поменяйте строку в `СформироватьPDF`.

> **Важно про учебную платформу.** Синтакс-контроль на учебной базе не видит модули
> УНФ — это нормально, потому что все обращения к ним динамические (`Вычислить`).
> Обработка всё равно сохраняется в `.epf` и корректно резолвит модули уже на сервере
> grach_unf при запуске. Ссылки на реквизиты документа (`Ссылка.Заказ`, `Ссылка.Номер`)
> синтакс-контроль тоже не проверяет — параметр `Ссылка` нетипизирован.
- **Поле «Заказ»** у Счёта на оплату может отсутствовать — код обёрнут в `Попытка`,
  тогда привязка идёт по `invoice_ref` (через счёт в TMS).

## XML УПД (ЭДО)

Эта обработка шлёт **печатные формы (PDF)**. Если нужен ещё и **XML электронного
документа** (формат ФНС) — это отдельная задача: в УНФ XML формирует подсистема ЭДО,
и проще тянуть его из связки с Saby/1С-ЭДО, чем из печати. Скажите, если нужен — добавим
тип `upd_xml` (TMS-эндпоинт его уже принимает).
