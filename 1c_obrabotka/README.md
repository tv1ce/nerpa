# Внешняя обработка «Отправка документов в NERPA» (вариант A — push из 1С)

Форма со списком **проведённых счетов за период** (по умолчанию текущий месяц,
период меняется). Пользователь выбирает счёт и жмёт **«Отправить в NERPA»** — только
тогда формируется PDF печатной формы и уходит в NERPA, который прикрепляет файл к
заказу.

```
1С (форма обработки) ──выбрал счёт→ Отправить──► NERPA POST /api/1c/order-document ──► файл в заказе
```

Преимущество перед расширением (.cfe): `.epf` грузится самим пользователем через
«Доп. обработки» по вебу (как Saby) — доступ к серверу базы не нужен.

---

## Состав

| Файл | Куда вставлять в Конфигураторе |
|---|---|
| `ОтправкаВTMS_МодульОбъекта.bsl` | Модуль объекта внешней обработки (регистрация в БСП) |
| `ОтправкаВTMS_МодульФормы.bsl`   | Модуль формы «Форма» (вся логика + настройки) |

Приёмная сторона NERPA: `app/routers/api_1c.py` — эндпоинт `POST /api/1c/order-document`
(уже задеплоен на проде).

---

## Настройки подключения (уже прописаны в модуле формы)

В функции `НастройкиTMS()` модуля формы:

```bsl
Хост  = "nuttshell.ru"   // домен NERPA — НЕ IP! (сертификат HTTPS выписан на домен)
Порт  = 443
HTTPS = Истина
Ключ  = "<ONEC_PUSH_KEY с сервера NERPA>"
```

> **Почему домен, а не IP.** NERPA работает по HTTPS с сертификатом на `nuttshell.ru`.
> По IP-адресу будет ошибка проверки сертификата. Всегда указывайте домен.

## Шаг 1. Создать внешнюю обработку

1. Конфигуратор (учебная 8.5.1) → **Файл → Новый → Внешняя обработка**.
2. Имя: `ОтправкаВTMS`.
3. **Модуль объекта** → вставить код из `ОтправкаВTMS_МодульОбъекта.bsl`.

## Шаг 2. Создать форму «Форма»

1. В дереве обработки → **Формы → Добавить → Форма обработки** → имя **`Форма`**,
   отметить **«Основная форма обработки»**. Готово (без конструктора-мастера).
2. На вкладке **Реквизиты** формы добавить:
   | Реквизит | Тип |
   |---|---|
   | `ПериодС` | Дата (состав «Дата») |
   | `ПериодПо` | Дата (состав «Дата») |
   | `ТаблицаСчетов` | ТаблицаЗначений |
   У `ТаблицаСчетов` добавить колонки (ПКМ по реквизиту-таблице → «Добавить реквизит»):
   | Колонка | Тип |
   |---|---|
   | `СчетGUID` | Строка (36) — GUID счёта, НЕ ссылка на документ |
   | `Номер` | Строка (20) |
   | `Дата` | Дата |
   | `Контрагент` | Строка (150) |
   | `Сумма` | Число (15, 2) |

   > Важно: колонка `СчетGUID` — обычная **Строка**, а НЕ `ДокументСсылка.СчетНаОплату`.
   > На учебной базе сборки нет конфигурации УНФ, поэтому тип-документ выбрать нельзя;
   > обработка хранит счёт строкой-GUID и восстанавливает документ в рантайме на боевой
   > УНФ через `Вычислить`. Никаких типов документов на форме не требуется.
3. На вкладке **Команды** формы добавить две команды: `Обновить` и `ОтправитьВTMS`.
4. **Элементы** формы (перетащить реквизиты/команды на форму):
   - поля `ПериодС`, `ПериодПо` (можно в одну группу-строку);
   - кнопка, связанная с командой `Обновить`;
   - **Таблица**, связанная с реквизитом `ТаблицаСчетов` (колонки Номер, Дата,
     Контрагент, Сумма — колонку `Счет` можно скрыть);
   - в командной панели таблицы — кнопка, связанная с командой `ОтправитьВTMS`.
5. **Модуль формы** → вставить весь код из `ОтправкаВTMS_МодульФормы.bsl`.

> Имена команд/реквизитов должны точно совпадать с кодом: `Обновить`,
> `ОтправитьВTMS`, `ПериодС`, `ПериодПо`, `ТаблицаСчетов`, `Элементы.ТаблицаСчетов`.

## Шаг 3. Сохранить и загрузить

1. **Файл → Сохранить как…** → `ОтправкаВTMS.epf`.
2. В 1С:Предприятии: **НСИ и администрирование → Печатные формы, отчёты и обработки
   → Дополнительные обработки → Добавить из файла** → выбрать `.epf` → согласиться с
   небезопасным режимом.
3. Запустить обработку из списка доп. обработок (раздел «Продажи» или из самого
   списка) — откроется форма.

## Шаг 4. Работа

1. Форма откроется со списком проведённых счетов **за текущий месяц**.
2. При необходимости поменять `ПериодС`/`ПериодПо` → кнопка **«Обновить»**.
3. Выделить нужный счёт → **«Отправить в NERPA»**.
4. Появится сообщение «Отправлено: счёт …». В карточке заказа NERPA появится **Счёт (PDF)**.

---

## Как определяется заказ в NERPA

Счёт уходит с `invoice_ref = GUID счёта`. NERPA находит заказ по
`Invoice.external_id_1c → order`. Поэтому счёт должен быть **синхронизирован в NERPA**
(pull-конвейер `sync_invoices_from_1c` уже это делает). Если заказ/счёт ещё не в NERPA —
вернётся понятная ошибка «заказ не найден».

Идемпотентность: повторная отправка заменяет прежний файл (`external_key = "<guid>:invoice"`),
дубль не плодится.

## Что уточнить под вашу редакцию УНФ

- **Имя макета счёта.** Обработка перебирает кандидатов `Счет,СчетНаОплату,…` и берёт
  первый сработавший. Если ни один не подошёл — в сообщении будет список опробованных;
  правильное имя добавить в строку `Кандидаты` в `ОтправитьСчетНаСервере`.
  Точный идентификатор: Конфигуратор → Документ.СчетНаОплату → команды/макеты печати.
- **Расширение на УПД.** Сейчас форма шлёт счета (`file_type=invoice`). Чтобы слать
  ещё и УПД — добавим в форму переключатель вида документа и запрос по
  `Документ.РасходнаяНакладная` (`file_type=upd`, эндпоинт NERPA его уже принимает).

## Учебная платформа — это нормально

Синтакс-контроль на учебной базе не видит модули УНФ (`УправлениеПечатью` и пр.) —
поэтому обращение к печати динамическое (`Вычислить`), а ссылки на реквизиты
документов нетипизированы. Обработка собирается на учебной, а модули резолвит уже на
боевой grach_unf при запуске.
