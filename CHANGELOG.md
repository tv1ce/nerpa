## [1.2.0] — 2026-06-04

### Безопасность
- Исправлены все 79 пунктов аудита безопасности (критические, высокий, средний, низкий приоритет)
- CSRF-защита на всех POST-формах (инъекция через `base.html` + валидация в декораторах)
- Шифрование секретов в БД (Fernet AES: токены, пароли интеграций)
- Rate limiting на `/auth/login` — 5 попыток / 5 минут по IP+логин
- `SECRET_KEY` и `ENCRYPT_KEY` из `.env`; предупреждение в лог при отсутствии
- Принудительная смена пароля при первом входе для пользователя admin
- Закрыты FastAPI `/docs` и `/redoc` в production
- Исправлен Path Traversal при загрузке шаблонов договоров и скачивании файлов
- Исправлен Stored XSS в комментариях к лидам и форме заказа
- Роль пользователя при каждом запросе читается из БД (не из cookie)

### Новые функции
- **Скидка по умолчанию**: поле `default_discount_pct` у контрагента автоматически применяется при создании заказа
- **KPI-фильтр**: настраиваемая подстрока для подсчёта штук на дашборде и в отчёте «Выручка» (ранее хардкод «орешк»)
- **Авто-просрочка счетов**: при старте сервера и каждый час `issued`+`due_date < today` → `overdue`
- **Ротация `generated/`**: файлы договоров старше 90 дней удаляются при старте
- **`/health` endpoint**: DB ping + uptime + HTTP 503 при недоступности БД
- **Telegram-бот**: напоминание о перезвонах на сегодня (`/callbacks`), команда `/status`
- **Табло цеха**: digital signage с метриками смены, мотивашками, веб-радио

### Производительность
- 13 новых индексов БД: `orders`, `invoices`, `order_items`, `invoice_items`, `sales_leads`, `audit_logs`, `stock_movements`
- N+1 запросы исправлены: `joinedload` в экспорте лидов, пересчёте категорий, GET балансов склада
- `_assembly_queue_count`: COUNT в SQL вместо загрузки всех заказов

### Инфраструктура и деплой
- `deploy/nginx.conf`: HTTP→HTTPS редирект, TLS Let's Encrypt, заголовки безопасности, upstream keepalive
- `deploy/tms.service`: systemd unit с автозапуском, изоляцией (`PrivateTmp`, `NoNewPrivileges`), journald-логами
- `deploy/backup.sh`: онлайн-бэкап SQLite через `.backup`, ротация 30 дней
- `deploy/logrotate.conf`: logrotate для Linux (daily, 30 дней, gzip)
- `run.py`: `setup_logging()` — `RotatingFileHandler` 10 МБ × 5 файлов; раздельные логи приложения и HTTP access
- `DATABASE_URL` читается из переменной окружения (для тестов и гибкого деплоя)
- FastAPI `lifespan` вместо устаревшего `@app.on_event("startup")`

### Android / PWA
- Android CI: `assembleRelease` вместо debug; keystore из GitHub Secrets; `versionCode` = `github.run_number`
- `app/static/offline.html`: брендированная offline-страница
- Service Worker v3: `offline.html` в PRECACHE, navigate-fallback из кеша
- PWA-иконки, манифест, maskable-иконки

### Качество кода
- `python-dotenv` добавлен в `requirements.txt` (использовался, но не был указан)
- Все `print()` заменены на `logging` (`logger.warning/info/error`)
- 14 `except: pass` в `logistics.py` → `logger.debug/warning`
- Версии зависимостей закреплены верхней границей `<X.0` (16 пакетов)
- Confirm-диалоги для удаления задач и комментариев на страницах заказа и контрагента
- Исправлен подсчёт кириллицы в SQLite (LOWER не работает → Python-фильтр + IN)
- `README.md`: полная документация деплоя, env-переменные, структура проекта

### Тесты
- `tests/test_smoke.py`: 18 smoke-тестов (health, auth flow, CSRF, все ключевые роуты)
- `tests/test_features.py`: 9 тестов фич (overdue, discount, offline page, health DB)
- `tests/conftest.py`: тестовая БД во временном файле, фикстуры `client` и `admin_client`
- `requirements-dev.txt`: pytest + httpx для тестирования

### Исправления
- Страница «Выручка» падала с `NameError` (`kpi_filter` использовался до определения)
- `nuts_year` и `nuts_this_month` всегда возвращали 0 (SQLite `LOWER()` не работает с кириллицей)
- Android APK подписывался debug-ключом вместо release
- Сессия жила 30 дней без серверной инвалидации → теперь проверяется `is_active` при каждом запросе
- `today` на дашборде показывал вчерашнюю дату после полуночи (был создан при старте сервера)

## [1.1.0] — 2026-05-28

### Добавлено
- Модуль «Разведка ЛПР»: обогащение точек прозвона через DaData (ИНН, ФИО руководителя, статус компании)
- Конвертация лида в контрагента одной кнопкой
- Табло цеха (board): digital signage для производственного помещения
- Отправка заказов перевозчику через Telegram
- Интеграция с Метафорой (Glide): импорт затрат на логистику
- Отчёт по логистике с детализацией по перевозчикам
- Генерация договоров из docx-шаблонов с подстановкой реквизитов

### Изменено
- Рабочий процесс заказа: добавлен статус `handed` («Передан поставщику»)
- Два цикла статусов: предоплата и отсрочка платежа
- Категоризация контрагентов A/B/C по объёму выручки
