# Расширение 1С: HTTP-сервис выдачи документов в TMS (Счёт PDF, УПД PDF, УПД XML)

Цель: TMS по запросу забирает из 1С готовые документы заказа и показывает кнопки
скачивания на карточке заказа:
- **Счёт** — PDF печатной формы (`Документ.СчетНаОплату`);
- **УПД** — PDF печатной формы (`Документ.РасходнаяНакладная`);
- **УПД для ЭДО** — XML в формате ФНС (формирует подсистема «Электронные документы»).

Архитектура — **pull**: 1С наружу не ходит, TMS сама дёргает HTTP-сервис на той же
публикации, где уже работает OData. Всё кладётся в **расширение конфигурации** —
основную УНФ не трогаем, поддержка не снимается.

> ⚠️ XML УПД формируется только если в этой УНФ доступна подсистема «Электронные
> документы / ЭДО» с форматом УПД (проверка — п. 6). PDF-часть работает всегда.

---

## 1. Контракт (что вызывает TMS)

База публикации: `http://srv4.life-it.pro/grach_unf/` (та же, что у OData).
HTTP-сервис: корневой URL `tms`, аутентификация — HTTP Basic тем же пользователем 1С,
что и OData.

| Запрос | Назначение | Ответ |
|---|---|---|
| `GET /grach_unf/hs/tms/print?type=invoice&ref=<guid>` | Счёт PDF | `application/pdf` |
| `GET /grach_unf/hs/tms/print?type=upd&ref=<guid>` | УПД PDF | `application/pdf` |
| `GET /grach_unf/hs/tms/edo?ref=<guid>` | УПД XML (ФНС) | `application/xml` |

- `ref` — `Ref_Key` (GUID строкой) документа: для `invoice` — `СчетНаОплату`,
  для `upd`/`edo` — `РасходнаяНакладная`. Эти GUID TMS уже знает (тянет документы по OData).
- Ошибка → код 500 + текст в теле (TMS залогирует, файл не приложит).

---

## 2. Создать расширение

Конфигуратор → «Конфигурация → Расширения конфигурации» → добавить новое
(имя, напр. `ИнтеграцияTMS`, назначение «Дополнение»). Либо в 1С:Предприятии:
«Администрирование → Печатные формы, отчёты и обработки → Расширения» → загрузить .cfe.

В расширение добавить: **общий модуль** `ИнтеграцияTMSСервер` (Сервер) и
**HTTP-сервис** `tms`.

---

## 3. HTTP-сервис `tms`

Свойства HTTP-сервиса:
- Корневой URL: `tms`
- Шаблоны URL:
  - `print` → URL-шаблон `/print`, метод `GET` → обработчик `ПечатьGET`
  - `edo` → URL-шаблон `/edo`, метод `GET` → обработчик `ЭДОGET`

Модуль HTTP-сервиса:

```bsl
Функция ПечатьGET(Запрос) Экспорт
    Тип = Запрос.ПараметрыЗапроса.Получить("type");
    Реф = Запрос.ПараметрыЗапроса.Получить("ref");
    Ответ = Новый HTTPСервисОтвет(200);
    Попытка
        PDF = ИнтеграцияTMSСервер.СформироватьPDF(Тип, Реф);
        Ответ.Заголовки.Вставить("Content-Type", "application/pdf");
        Ответ.УстановитьТелоИзДвоичныхДанных(PDF);
    Исключение
        Ответ.КодСостояния = 500;
        Ответ.УстановитьТелоИзСтроки(ОписаниеОшибки());
    КонецПопытки;
    Возврат Ответ;
КонецФункции

Функция ЭДОGET(Запрос) Экспорт
    Реф = Запрос.ПараметрыЗапроса.Получить("ref");
    Ответ = Новый HTTPСервисОтвет(200);
    Попытка
        XML = ИнтеграцияTMSСервер.СформироватьУПД_XML(Реф);
        Ответ.Заголовки.Вставить("Content-Type", "application/xml; charset=utf-8");
        Ответ.УстановитьТелоИзСтроки(XML, КодировкаТекста.UTF8);
    Исключение
        Ответ.КодСостояния = 500;
        Ответ.УстановитьТелоИзСтроки(ОписаниеОшибки());
    КонецПопытки;
    Возврат Ответ;
КонецФункции
```

## 4. Общий модуль `ИнтеграцияTMSСервер` — PDF печатных форм

```bsl
// type: "invoice" (СчетНаОплату) | "upd"/"tn" (РасходнаяНакладная)
Функция СформироватьPDF(Тип, РефСтр) Экспорт
    Если Тип = "invoice" Тогда
        Ссылка = Документы.СчетНаОплату.ПолучитьСсылку(Новый УникальныйИдентификатор(РефСтр));
        ИмяМакета = "Счет";              // ← уточнить, см. п.6
    Иначе
        Ссылка = Документы.РасходнаяНакладная.ПолучитьСсылку(Новый УникальныйИдентификатор(РефСтр));
        ИмяМакета = ?(Тип = "tn", "ТоварнаяНакладная", "УПД");   // ← уточнить, см. п.6
    КонецЕсли;

    Объекты = Новый Массив; Объекты.Добавить(Ссылка);
    Макеты  = Новый Массив; Макеты.Добавить(ИмяМакета);
    ТабДоки = Новый СписокЗначений;

    // Стандартный вызов подсистемы печати БСП
    УправлениеПечатью.ПечататьНаборФорм(Макеты, Объекты, ТабДоки, , , );

    ТабДок = Неопределено;
    Для Каждого Эл Из ТабДоки Цикл ТабДок = Эл.Значение; Прервать; КонецЦикла;
    Если ТабДок = Неопределено Тогда
        ВызватьИсключение "Печатная форма не сформирована: " + ИмяМакета;
    КонецЕсли;

    Поток = Новый ПотокВПамяти;
    ТабДок.Записать(Поток, ТипФайлаТабличногоДокумента.PDF);
    Возврат Поток.ЗакрытьИПолучитьДвоичныеДанные();
КонецФункции
```

> Если в вашей УНФ нет `УправлениеПечатью.ПечататьНаборФорм`, используйте
> `УправлениеПечатью.СформироватьПечатныеФормы(...)` или прямой вызов процедуры
> `Печать` из модуля менеджера документа — итог один: получить `ТабличныйДокумент`,
> затем `ТабДок.Записать(Поток, ТипФайлаТабличногоДокумента.PDF)`.

## 5. Общий модуль — УПД в формате ЭДО (XML ФНС)

УПД-XML формирует штатная подсистема «Электронные документы» (та же, что по кнопке
«ЭДО → Выгрузить электронный документ в файл» на расходной накладной). Точное имя
метода зависит от версии БСП/ЭДО в вашей УНФ — каркас:

```bsl
Функция СформироватьУПД_XML(РефСтр) Экспорт
    Ссылка = Документы.РасходнаяНакладная.ПолучитьСсылку(Новый УникальныйИдентификатор(РефСтр));

    // ВАРИАНТ А (рекомендуется): тот же механизм, что «Выгрузить в файл» в ЭДО.
    // Имя метода уточнить в вашей конфигурации (модули ЭлектронныеДокументыСлужебный /
    // ОбменЭлектроннымиДокументами / ФорматУниверсальныйПередаточныйДокумент).
    // Метод должен вернуть строку XML (или ДвоичныеДанные/имя временного файла).
    XMLСтрока = ЭлектронныеДокументыСлужебный.СформироватьXMLэлектронногоДокумента(Ссылка);
    Возврат XMLСтрока;

    // ВАРИАНТ Б: если метод отдаёт во временный файл —
    //   ИмяФайла = ...; Текст = Новый ЧтениеТекста(ИмяФайла, КодировкаТекста.UTF8);
    //   Возврат Текст.Прочитать();
КонецФункции
```

Как найти реальный метод (для 1С-специалиста):
1. Открыть расходную накладную в 1С → меню «ЭДО» → убедиться, что есть «Выгрузить
   электронный документ в файл» (если команды нет — формат УПД в этой УНФ не
   подключён, см. п.6).
2. Через отладчик/глобальный поиск найти процедуру, вызываемую этой командой —
   обычно в `ОбщийМодуль.ЭлектронныеДокументыСлужебныйКлиент`/`...Служебный` либо в
   модуле формата `ФорматУниверсальныйПередаточныйДокумент`. Использовать её
   серверную часть, возвращающую XML/двоичные данные.

## 6. Что должен проверить/уточнить 1С-специалист

1. **Имена макетов печати** (`ИмяМакета`) для Счёта и УПД — открыть документ →
   «Печать», посмотреть имена команд печати (или модуль менеджера документа). В УНФ
   типично: счёт — `Счет`/`СчетНаОплату`; УПД — `УПД`; ТН — `ТоварнаяНакладная`.
2. **Доступность XML-УПД**: есть ли на расходной накладной команда «ЭДО → Выгрузить
   в файл». Если нет — XML из 1С не получить (тогда обсудим генерацию XML на стороне
   TMS как отдельный этап).
3. **Публикация HTTP-сервисов**: в публикации базы на веб-сервере должны быть
   разрешены HTTP-сервисы (галочка при публикации). Раз OData работает — публикация
   есть; возможно, надо переопубликовать с включёнными HTTP-сервисами и добавить
   сервис `tms` в состав.
4. **Права**: пользователю 1С, под которым ходит TMS, нужны права на чтение
   документов и на печать/выгрузку ЭД.

## 7. Проверка после установки

В браузере (с авторизацией пользователя 1С) открыть, подставив реальный GUID счёта:
```
http://srv4.life-it.pro/grach_unf/hs/tms/print?type=invoice&ref=<guid-счёта>
```
Должен скачаться PDF. Аналогично `type=upd&ref=<guid-расходной>` и `/edo?ref=<guid-расходной>`.

После того как все три URL отдают корректные файлы — сообщите мне, и я подключаю
TMS-сторону: TMS будет тянуть `РасходнаяНакладная` по OData, сопоставлять с заказом,
забирать PDF/XML и показывать кнопки скачивания на карточке заказа.
