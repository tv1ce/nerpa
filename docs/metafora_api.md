# Метафора API — интеграция для клиентов доставки

«Метафора» — курьерская служба доставки. Метафора API позволяет вашей системе
(бот, NERPA, CRM, интернет-магазин) передавать заказы на доставку и получать
статусы их выполнения. Документ самодостаточен: по нему можно подключиться
с нуля, без других договорённостей.

База API: `https://api.damasevich.ru`

---

## 1. Как это работает

- **Вы создаёте заказы** вызовом `POST /orders` со своим API-токеном.
- Заказ появляется в рабочем чате Метафоры: карточка с разбором по полям
  (адрес, дата, время, телефоны, выручка) — логист видит его так же, как заказы
  из почты и Telegram. Заказ создаётся в диспетчерской системе.
- **Опционально**: если у вас есть своя система и вы хотите получать статусы
  («в пути», «доставлено») автоматически — вы поднимаете приёмный эндпоинт
  (раздел 4) и передаёте нам его URL и ключ. Метафора шлёт на него статусы
  (раздел 5). Приёмника нет — не страшно: исполнение заказа видно в чате,
  а статусы вашей команде передаёт менеджер как обычно.

## 2. Подключение

1. Менеджер Метафоры выдаёт вам **API-токен** (длинная случайная строка).
2. Токен передаётся в каждом запросе заголовком:

   ```
   Authorization: Bearer <ВАШ_ТОКЕН>
   ```

3. (Опционально) Для статусов: поднимаете приёмник по разделу 4, генерируете
   **свой ключ** (им защищается ваш приёмник — ключ выдаёт владелец приёмника)
   и передаёте менеджеру URL приёмника + свой ключ + способ передачи ключа
   (query-параметр или заголовок).

Токен — секрет. Не публикуйте его, не кладите в клиентский код и репозитории.
При компрометации — запросите перевыпуск, старый токен отзывается.

## 3. Создание заказа — `POST /orders`

Один метод, две формы тела на выбор.

### 3а. Свободный текст (разбирает парсер Метафоры)

```json
{"external_id": "83", "text": "Доставка, Бухарестская ул 30, завтра до 17, +7 921 111-22-33, диван, получить 3280"}
```

Текст — в том виде, в каком вы отправили бы заказ менеджеру в чат: адрес,
дата/день недели, время, телефоны, что везти, выручка. Парсер разберёт
(тот же, что разбирает письма и Telegram-сообщения клиентов).

### 3б. Структурные поля (без парсера, сразу в систему)

```json
{"external_id": "83", "address": "Бухарестская ул 30", "date": "2026-08-05",
 "time": "До 17", "phone_1": "+79211112233", "what_to_carry": "диван",
 "revenue_type": "Получить", "revenue_amount": 3280}
```

| Поле | Тип | Обяз. | По умолчанию |
|---|---|---|---|
| `address` | строка | **да** | — |
| `date` | строка `ГГГГ-ММ-ДД` | нет | сегодня |
| `service` | «Доставка» / «Забор» | нет | «Доставка» |
| `time` | строка («До 17», «14:00-15:00») | нет | — |
| `how_to_find` | строка (квартира, код, этаж) | нет | — |
| `phone_1`, `phone_2` | строка, формат любой (нормализуем) | нет | — |
| `what_to_carry` | строка | нет | — |
| `order_number` | строка (ваш номер для курьера/накладных) | нет | — |
| `weight_kg`, `volume_m3` | число | нет | — |
| `long_item` | `true` (длинномер: сторона ≥ 2 м) | нет | отсутствует |
| `documents` | `true` (нужны документы/печать) | нет | отсутствует |
| `no_call` | `true` (не звонить клиенту) | нет | отсутствует |
| `important` | строка (пометка логисту) | нет | — |
| `comment` | строка | нет | — |
| `link` | строка (ссылка) | нет | — |
| `geo` | строка (координаты) | нет | — |
| `revenue_type` | «Без выручки» / «Получить» / «Оплатить» | нет | «Без выручки» |
| `revenue_amount` | целое ≥ 0 (руб.) | нет | — |

### external_id — защита от дублей

`external_id` (ваш внутренний номер заказа) **обязателен** в обеих формах.
Это ключ идемпотентности: если сеть мигнула и вы повторяете запрос с тем же
`external_id`, заказ не задвоится — вернётся `409 duplicate`, который следует
трактовать как успех («заказ уже принят»).

### Ответы

| Код | Тело / смысл |
|---|---|
| 200 | `{"status": "ok", "n_orders": 1, "warnings": [], "note": ""}` — принято. `status` также `no_orders` (в тексте не нашлось заказа) и `parse_error` (текст не разобран, причина в `note`) — заказ не создан, проверьте данные |
| 409 | `duplicate` — этот `external_id` уже обработан (= успех) |
| 401 | неверный или отсутствующий токен |
| 422 | ошибка в теле (поля в `detail`) |
| 503 | временный сбой на стороне Метафоры — ретрайте с тем же `external_id` |
| 500 | внутренняя ошибка — сообщите менеджеру |

**Таймаут:** текстовая форма может обрабатываться до минуты (парсер) — ставьте
таймаут клиента **≥ 60 секунд**. Ретраи безопасны благодаря `external_id`.

## 4. Ваш приёмный эндпоинт для статусов (опционально)

Если хотите получать статусы в свою систему автоматически. Требования к
приёмнику (ваша сторона):

- HTTPS, `POST` на ваш URL.
- Аутентификация **вашим ключом** (query-параметр или заголовок — как
  договорились при подключении). Неверный/отсутствующий ключ → `401`.
- Тело запроса от Метафоры:

  ```json
  {"order": "83", "address": "Бухарестская ул 30", "status": "доставлено",
   "comment": "принял Иванов", "ts": "2026-08-05T15:30:00+03:00"}
  ```

  `order` = ваш `external_id` (если заказ создан через API; может отсутствовать,
  если заказ пришёл в Метафору другим каналом — тогда сопоставляйте по
  `address`). `address` — всегда.
- **Идемпотентность обязательна**: повторный запрос с тем же статусом безопасен
  (ничего не меняет).
- Ответ: `200` с JSON `{"ok": true|false, "reason": "...", "message": "..."}`;
  `reason`: `ok` / `order_not_found` / `ambiguous` (по адресу несколько активных
  заказов — нужен `order`) / `unknown_status`. Человекочитаемое `message`
  попадает в журнал на стороне Метафоры.
- Статусы v1: **«доставлено»** (заказ закрыт) и **«в пути»** (курьер принял заказ).
  Распознавание может быть мягким (по вхождению слова): «Доставлено клиенту»
  тоже подойдёт. Неизвестный статус — заказ не трогать, вернуть `unknown_status`.
- Рекомендуется `GET /ping` (или аналог) для проверки связи: `{"ok": true}`.

### Пример минимального приёмника (псевдокод)

```
POST /callback/metaphora?key=<МОЙ_КЛЮЧ>
  тело: {order?, address, status, comment?, ts}
  найти заказ по order, иначе по address (если один активный)
  сменить статус идемпотентно → {"ok": true, "reason": "ok", ...}
```

## 5. Что Метафора шлёт вам

При смене статуса заказа Метафора отправляет `POST` на ваш URL с вашим ключом
(способ из п.2). Тело — как в разделе 4. В v1 события два: «в пути» и
«доставлено». Если ваш эндпоинт недоступен в момент события — доставка
запроса в v1 не ретраится (логируется на нашей стороне); исполнение заказа
от этого не зависит. Статусы можно дослать вручную через менеджера.

Сопоставление заказа у вас: надёжнее всего по `order` (ваш `external_id`);
заказы не из API — по `address`.

## 6. Примеры curl

Создать заказ полями:

```bash
curl -X POST https://api.damasevich.ru/orders \
  -H "Authorization: Bearer ВАШ_ТОКЕН" -H "Content-Type: application/json" \
  -d '{"external_id":"83","address":"Бухарестская ул 30","date":"2026-08-05","time":"До 17","phone_1":"+79211112233"}'
```

Создать заказ текстом:

```bash
curl -X POST https://api.damasevich.ru/orders \
  -H "Authorization: Bearer ВАШ_ТОКЕН" -H "Content-Type: application/json" \
  -d '{"external_id":"84","text":"Забор, Пулковская ул 10, в пятницу, выручка 1500 оплатить"}'
```

Повтор того же external_id (идемпотентность):

```bash
# тот же запрос ещё раз → 409 {"status":"duplicate",...} — это успех
```

## 7. Вопросы и ответы

- **Нужен ли приёмник статусов, чтобы пользоваться API?** Нет. Приём заказов
  работает без него; исполнение видно в чате с Метафорой.
- **Что делать при 503?** Повторить запрос с тем же `external_id` — заказ не
  задвоится.
- **Что значит 409?** Заказ с этим `external_id` уже принят. Считайте успехом.
- **Можно ли слать несколько заказов одним запросом?** В v1 — один заказ на
  запрос (один `external_id`). Несколько адресов — несколько запросов.
- **Куда писать, если что-то не работает?** Менеджеру Метафоры; приложите
  `external_id` и время запроса.
